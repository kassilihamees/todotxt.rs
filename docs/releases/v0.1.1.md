# v0.1.1 — Verified saves and local recovery

Safety update following a report that completing a task on a Windows rclone
mount immediately left the task file empty. Automatic archive was disabled;
automatic refresh was enabled. v0.1.0 is marked with a critical warning.

## Changes

- Close the staged write handle before replacing the destination. This avoids
  renaming a file with its writer still open, a problematic pattern for some
  mounted filesystems.
- Read back the staged bytes before replacement and the destination bytes
  afterward. A filesystem operation returning success is no longer enough.
- Recheck source and archive contents immediately before replacement.
- Retain local `previous.txt` and `intended.txt` recovery copies before task or
  archive replacement. Failed operations retain separate snapshots. A save
  verification error reports their location, keeps the previous in-memory
  tasks, and pauses automatic refresh until explicit recovery/reload.

Windows recovery copies are under `%LOCALAPPDATA%\todotxt.rs\data\recovery`.
These contain task data and must remain private. Per-file copies are refreshed
before each save; separate failed-save snapshots are retained until manually
removed. This is recovery protection, not automatic merging or version control.

## Validation and limits

Passed on Windows: 27 task/file tests, seven portable GUI tests, formatting,
strict Clippy for both frontends, optimized build and the native GUI smoke check.
Additional regressions simulate replacement reporting success but truncating
the destination, verify recovery and retained memory/refresh state, and check
that the staged handle is closed and external changes are rechecked.

The updated native app also passed ten completion toggles on an isolated,
fictional file on the maintainer's actual rclone mount with automatic refresh
enabled. Both tasks and the task list remained intact. No live task file was
modified during validation.

The original reported failure could not be reproduced with the old writer
during isolated tests, including files first uploaded directly to the remote.
Its precise cause remains unconfirmed. This update addresses a save-handle
risk and adds detection/recovery; it does not promise that every cloud driver
will implement atomic replacement correctly. Read-back verification sees the
mounted view, not the eventual remote cloud state after delayed uploads.
Keep independent backups and confirm important cloud edits have synchronized.

Download `todotxt-rs-v0.1.1-windows-x86_64.zip`, extract it, and run the executable.
No installer is required; existing preferences remain in the user's profile.
The ZIP includes public documentation and the BSD license; `SHA256SUMS.txt`
contains its checksum. Linux build/runtime and GitHub-hosted CI remain pending.
The parity gaps and deferred features from v0.1.0 still apply.
